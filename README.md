# sohailabbas.site — 20 free browser-based tools

A complete, fast, mobile-first tool site built with plain HTML, CSS and vanilla JavaScript.
**Every tool works.** 19 of 20 process data entirely in the browser; the 20th (Word → PDF)
also runs client-side and is deliberately text-focused.

- No framework, no npm install, no build step at runtime.
- No cookies, no analytics, no third-party requests at runtime (libraries are vendored locally).
- Generated by one Python file (`build.py`), standard library only.

## Build

```bash
cd sohailabbas-site
python3 build.py --check      # build + validate SEO constraints
```

`--check` fails the build on: duplicate or out-of-range titles/descriptions, missing canonical,
more than one `<h1>`, invalid JSON-LD, or an `<img>` without alt text.

Preview locally:

```bash
cd site && python3 -m http.server 8090
```

## Deploy

1. In `build.py` set `SITE_URL = "https://sohailabbas.site"` (already the default) and `CONTACT_EMAIL`.
2. `python3 build.py`
3. Upload the **contents of `site/`** to any static host (Netlify, Vercel, Cloudflare Pages, GitHub
   Pages, S3, Nginx/Apache).
4. Point `404.html` at your host's error handler. Unknown URLs should return HTTP 404.
5. Choose one canonical host (with or without `www`) and 301 the other.

Clean URLs (`/tools/vat-calculator/`) are directory-index pages, so they work on every static host
with no rewrite rules.

> Note: clipboard buttons and (harmlessly) nothing else need a secure context. Over `https://` or
> `localhost` everything works. Over `file://` the copy buttons are the only degraded feature; all
> results remain visible and selectable.

## Editing

**Change a tool's SEO copy** — edit `src/data/tools-*.json` and rebuild. Each entry holds
`meta_title` (50–60 chars), `meta_description` (140–160), `h1`, `primary_keyword`, 5–10
`longtails`, `related_terms`, `faqs`, `examples`, `features`, `intro` and an `editorial_note`.

**Change the ranking** — the `rank` field (1–20, contiguous) controls the homepage order and the
`ItemList` structured data. The build fails if ranks are duplicated or skipped.

**Change a tool's behaviour** — edit the matching `src/tools/<slug>.html`. Keep `<script>` inline and
keep ids prefixed with the tool's short code so nothing collides if pages are ever combined.

**Add a tool** — add a JSON entry, create `src/tools/<slug>.html`, bump the count assertion in
`load_tools()`, and update the "20" strings in `build.py` (hero, titles, footer).

## What was verified before delivery

- 33 pages built; `--check` passes (unique titles 45–62 chars, descriptions 135–165, one `h1`,
  canonical, valid JSON-LD, alt text on every image).
- All 20 tools load with **zero console or page errors** in headless Chrome.
- Functional tests executed per tool: VAT add/extract and rate switching, percentage all 4 modes,
  salary both directions, EMI + extra payment (250,000 @ 9.5%/20y → 2,330/mo, 309,279 interest),
  stacked discounts, date duration weekdays, age breakdown, overtime two bands, tip split,
  BMI metric+imperial, word count, case styles, time zone conversions, text diff, JSON validation
  with error position, **PDF merge (2 files → 5 pages), image compression, images → PDF,
  JPG → PNG, and DOCX → PDF**, then confirmed each produced a working download.
- Mobile layout checked at 390 × 844 on the homepage and a tool page.

## Honest limitations (stated on the pages, repeated here)

- **Keyword metrics are not verified.** No Google Keyword Planner / Ahrefs / Semrush access was
  available, so search volume and KD are labelled `NOT VERIFIED` in the spreadsheet — never invented.
  See the workbook's "How to verify" sheet for the exact procedure to fill them in.
- Salary/net-pay, tax-filing and currency tools were deliberately **not** built: they need
  continuously verified jurisdiction data, and a stale figure would mislead people.
- Word → PDF rebuilds text rather than rendering Word's layout: images, tables, columns and custom
  fonts are not reproduced. The page says so and points to Word/LibreOffice for pixel-exact output.
- PDF tools cannot open password-protected files (by design).
- Finance/health results are estimates using published formulas — not financial, tax, legal or
  medical advice. No rankings, earnings or AdSense approval are promised anywhere.
