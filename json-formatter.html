What the JSON Formatter does

JSON has no comments and no tolerance for mistakes. A trailing comma, a single quote instead of double quotes, or an unquoted key makes the whole document unparseable, and the browser's default message rarely tells you where the problem is.

This formatter pretty-prints with your chosen indentation, minifies for production, and reports the exact line and character where parsing failed. It also counts keys and measures nesting depth, which is a quick way to check whether a response is the shape you expected before you write code against it.

How to use it

  1. Paste the JSON, or load the sample to see the tool working.
  2. Press Format to beautify, or Minify to compress to a single line.
  3. Read the status line — valid JSON confirms the structure, invalid JSON gives a position.
  4. Copy the output straight into your editor, request body or config file.

Features

  • Pretty print with 2 or 4 spaces, or tabs
  • Minify to a single line for production payloads
  • Error reports with line and character position
  • Key count and maximum nesting depth
  • Byte comparison between input and output

Worked examples

A trailing comma

{"a":1,} fails because JSON does not allow a comma before a closing brace, even though JavaScript object literals do. The validator points at the position of the closing brace.

Minifying for a payload

A 2 KB formatted config typically compresses to around 1.2 KB minified. If the payload is sent compressed with gzip or Brotli, the difference in transfer size is much smaller than the raw byte count suggests.

Frequently asked questions

Why is my JSON invalid?

The most common causes are a trailing comma, single quotes instead of double quotes, an unquoted key, a missing bracket, or a value like undefined or NaN that JSON does not support. The validator reports the line and character where parsing stopped.

Does formatting change the data?

No. Whitespace is insignificant in JSON, so beautifying or minifying produces identical data with a different layout. Key order is preserved as written, and duplicate keys resolve to the last one in most parsers — which is itself a bug worth fixing.

Is my JSON uploaded to a server?

No. Parsing uses the browser's built-in JSON engine. That matters for tokens, customer data and internal payloads, which should never be pasted into a server-side tool.

Can this validate against a JSON Schema?

No. It validates syntax, not shape. For schema validation you need a library such as Ajv, and you would define required fields, types and value constraints yourself.
