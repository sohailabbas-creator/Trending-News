Why client-side file tools are different

Upload-based converters have to store your file at least temporarily, and free tiers often come with page limits, watermarks or waiting queues. Client-side tools read the file into browser memory, transform it, and hand back a download. There is no upload step, no server copy and no queue. It also means the tools keep working offline, which matters on a train or on a locked-down network.

What that trade-off costs

Honesty matters more here than anywhere else. Very large files are limited by your device's memory rather than a server farm, so a phone will struggle where a laptop copes. Password-protected PDFs are not unlocked. The Word to PDF converter rebuilds text rather than rendering Word's layout engine, so complex designs lose their formatting. Each page says what it does not do, because a misleading conversion wastes more time than a clear refusal.

A practical order of operations

If a combined document is too large to email, compress or downscale the images first, then build or merge the PDF. Merging and then compressing is harder to control, because you can no longer tune the quality of each source image.
